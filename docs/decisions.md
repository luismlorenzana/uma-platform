# Decisions Log — cross-game

Platform-wide decisions that bind every Uma repo. Game-specific decisions live in each game's `docs/decisions.md`.
Newest entries at the bottom. To reverse a decision, add a new entry that supersedes it instead of editing history.

| # | Date | Decision | Why / Notes |
|---|---|---|---|
| P1 | 2026-10-10 | Personal use only, never distributed. All repos private | Uses third-party IP, same as uma-racer D1 |
| P2 | 2026-10-10 | **Three standalone games** (uma-racer, uma-rpg, uma-puzzle) plus **uma-platform**, each in its own repo | Owner: isolated codebases and data, each advanced in its own agent sessions |
| P3 | 2026-10-10 | Games never import from each other, read each other's saves, or share an economy | Independent development cycles. uma-rpg stops being a token source for uma-racer |
| P4 | 2026-10-10 | **No save carry-over.** uma-rpg and uma-puzzle start fresh; uma-racer drops its RPG and puzzle save data | Owner decision |
| P5 | 2026-10-10 | uma-platform is the **single source of truth for master data**: characters, outfits with full stats, support cards, skills, scenarios, races, courses, objectives, and Uma art | Import new releases once, available in every game |
| P6 | 2026-10-10 | Original-game content never goes in git or on a public host. Releases live in a private bucket and reach games only through their logged-in APIs | Carries over uma-racer's rule |
| P7 | 2026-10-10 | Games follow the latest master data release within their schema major. Breaking changes bump the major and need a deliberate upgrade | New content flows automatically; breaking changes never surprise a game |
| P8 | 2026-10-10 | Games reference master data only by the original game's stable IDs, adapt it through one adapter module, and keep Uma leveling per game | Shared baseline data with separate data structures |
| P9 | 2026-10-10 | Shared code ships as private GitHub Packages under `@luismlorenzana/*`, versioned with Changesets; games pin exact versions | Separate repos with heavy reuse, upgraded on each game's own schedule |
| P10 | 2026-10-10 | All three games get a similar Hub, farm-like passive generators and per-game Uma leveling | Owner decision |
| P11 | 2026-10-10 | **Extract on second use**: only `uma-data` is shared up front. Hub, farm and idle code are built in uma-rpg first and extracted during the uma-racer refactor | A kit designed before any game uses it usually guesses wrong |
| P12 | 2026-10-10 | uma-planner is out of scope, except as a possible one-time source for initial loads into uma-platform | Owner decision |
| P13 | 2026-10-10 | New games start from the uma-racer stack (React, Vite, Tailwind, Motion, Zustand + Dexie, NestJS on Cloud Run, Firebase Hosting + Auth, PWA), one Firebase/GCP project per game | Proven on the owner's iPhone; one setup to maintain |
| P14 | 2026-10-10 | **Phaser 4** for new canvas scenes (maps, battles, Hub). uma-racer's PixiJS scenes stay until reworked | Built-in tile maps, camera, tweens and sprite animation fit Fire Emblem/Wargroove-style visuals. Recommendation; revisit after the first Hub prototype |
| P15 | 2026-10-10 | Original art lives in `uma-platform/assets/`, generated by scripts, in git | It's original, so it's safe in git, and scripts keep it reproducible |
| P16 | 2026-10-10 | Order: Phase 0 platform → 1 uma-rpg foundation → 2 uma-rpg Hub/Farm → 3 uma-racer refactor → 4 uma-puzzle | Owner's preference: build the RPG and Hub first, then refactor uma-racer with what was learned |
| P17 | 2026-10-10 | No new RPG or puzzle features in uma-racer until Phase 3 | Avoids porting a moving target |
