# Decisions Log — cross-game

Platform-wide decisions that bind every Uma repo. Game-specific decisions live in each game's `docs/decisions.md`.
Newest entries at the bottom. To reverse a decision, add a new entry that supersedes it instead of editing history.

| # | Date | Decision | Why / Notes |
|---|---|---|---|
| P1 | 2026-10-10 | Personal use only, never distributed. All repos private | Uses third-party IP, same as uma-racer D1 |
| P2 | 2026-10-10 | **Three standalone games** (uma-racer, uma-rpg, uma-puzzle) plus **uma-platform**, each in its own repo | Owner: isolated codebases and data, each advanced in its own agent sessions |
| P3 | 2026-10-10 | Games never import from each other, read each other's saves, or share an economy | Independent development cycles. uma-rpg stops being a token source for uma-racer |
| P4 | 2026-10-10 | **No save carry-over.** uma-rpg and uma-puzzle start fresh; uma-racer drops its RPG and puzzle save data | Owner decision |
| P5 | 2026-10-10 | uma-platform is the **single source of truth for master data**: characters, outfits with full stats, support cards, skills, scenarios, races, courses, objectives, and Uma art | Import new releases once, available in every game |
| P6 | 2026-10-10 | Original-game content never goes in git or on a public host. Releases live in a private bucket and reach games only through their logged-in APIs | Carries over uma-racer's rule |
| P7 | 2026-10-10 | Games follow the latest master data release within their schema major. Breaking changes bump the major and need a deliberate upgrade | New content flows automatically; breaking changes never surprise a game |
| P8 | 2026-10-10 | Games reference master data only by the original game's stable IDs, adapt it through one adapter module, and keep Uma leveling per game | Shared baseline data with separate data structures |
| P9 | 2026-10-10 | Shared code ships as private GitHub Packages under `@luismlorenzana/*`, versioned with Changesets; games pin exact versions | Separate repos with heavy reuse, upgraded on each game's own schedule |
| P10 | 2026-10-10 | All three games get a similar Hub, farm-like passive generators and per-game Uma leveling | Owner decision |
| P11 | 2026-10-10 | **Extract on second use**: only `uma-data` is shared up front. Hub, farm and idle code are built in uma-rpg first and extracted during the uma-racer refactor | A kit designed before any game uses it usually guesses wrong |
| P12 | 2026-10-10 | uma-planner is out of scope, except as a possible one-time source for initial loads into uma-platform | Owner decision |
| P13 | 2026-10-10 | New games start from the uma-racer stack (React, Vite, Tailwind, Motion, Zustand + Dexie, NestJS on Cloud Run, Firebase Hosting + Auth, PWA), one Firebase/GCP project per game | Proven on the owner's iPhone; one setup to maintain |
| P14 | 2026-10-10 | **Phaser 4** for new canvas scenes (maps, battles, Hub). uma-racer's PixiJS scenes stay until reworked | Built-in tile maps, camera, tweens and sprite animation fit Fire Emblem/Wargroove-style visuals. Recommendation; revisit after the first Hub prototype |
| P15 | 2026-10-10 | Original art lives in `uma-platform/assets/`, generated by scripts, in git | It's original, so it's safe in git, and scripts keep it reproducible |
| P16 | 2026-10-10 | Order: Phase 0 platform → 1 uma-rpg foundation → 2 uma-rpg Hub/Farm → 3 uma-racer refactor → 4 uma-puzzle | Owner's preference: build the RPG and Hub first, then refactor uma-racer with what was learned |
| P17 | 2026-10-10 | No new RPG or puzzle features in uma-racer until Phase 3 | Avoids porting a moving target |
| P18 | 2026-10-10 | `uma-data` validators are **hand-written explicit parsers** (`fields(value, path)('id', positiveInteger)`), in the style of uma-racer's `save.types.ts`, with no schema library. They throw `MasterDataError` with the JSON path of the first bad value and **ignore keys they don't know** | No runtime dependency in a package every game ships; errors name the exact field; ignoring unknown keys lets a newer minor release pass an older client (P7). uma-racer's `exactKeys` strictness fits saves, not forward-compatible releases |
| P19 | 2026-10-10 | Master ids are **JSON integers**, the original's numeric ids. Games convert at their adapter (uma-racer: `String(id)`) | Faithful to the original (P8); every source id is numeric; the values match uma-racer's string ids exactly, so saves keep working |
| P20 | 2026-10-10 | **Japan is the base, Global overrides on top.** Text is `{ ja, en, global }`; lists and mechanics that differ on Global get a `global…` field. Korean and Taiwanese servers keep only release dates and flags | uma-racer prefers Global and needs both; KR/TW text and mechanics aren't used by any game and would double the skill set's size |
| P21 | 2026-10-10 | **Codes stay codes**: the original's numeric codes (race grade, terrain, direction, season, effect and condition types…) are kept as numbers with exported label tables. Only vocabularies fixed by game design are words (stats, aptitude grades and groups, servers, support-card types). Growing vocabularies (`obtain`, outfit variant, skill tags) are plain strings | A new code in a minor release can't break an older client's parser; the codes are what the original uses; words where every game needs them and they can't change |
| P22 | 2026-10-10 | Master data keeps **every record and rarity**: all support-card rarities, every skill rarity including evolved (6), each inherited (gene) version as its own skill record, every race grade and venue. Games filter in their adapter | Superset of uma-racer (which kept SSRs, non-evolved skills, five grades and 15 venues) so other games aren't limited by its choices |
| P23 | 2026-10-10 | **Release layout final** (architecture §2.2): `files/{data,atlases,art}/…/<stem>.<sha256[0:16]>.<ext>`, `manifests/v1/<version>.json`, `channels/v1/latest.json`. Version = 12 hex of SHA-256 over the sorted file hashes (uma-racer's algorithm). Files and manifests are uploaded with `--no-clobber` and never deleted; an existing manifest for the same version must list identical files; the channel is the only object ever replaced (`no-cache`). Garbage collection is deferred; when needed it may delete only objects no published manifest references | Content addressing makes publishing idempotent and rollback a channel move; 16 hex characters keep shared names collision-free across releases |
| P24 | 2026-10-10 | Art is described by **one art index per release** (`data/art.<hash>.json`, `manifest.art`) holding atlas descriptors and per-record image paths. Families have neutral names (`outfit-icons`, `support-card-icons`, `skill-icons`, `scenario-icons`, `outfit-portraits`, `outfit-busts`, `support-card-art`, `outfit-chibis`, `character-dresses`, `character-faces`). Every family skips a missing source with a warning instead of failing | One fetch tells a game all the art there is; uma-racer's atlas JSON files and path patterns become lookups; a GameTora gap (new cards' illustrations lag) shouldn't block a release |
| P25 | 2026-10-10 | **Source URLs aren't master data.** uma-racer's `imageSource` is dropped; the asset pipeline derives GameTora image URLs from ids (`scripts/assets/src/sources.ts`) | URLs describe a website, not the game; deriving them keeps records neutral and the derivation in one place |
| P26 | 2026-10-10 | Scenario crests derive from the scenario id. uma-racer's private `scenario-icons.json` was copied into `content/overrides/` and **re-keyed from its slugs to GameTora scenario ids** (the id in each URL); every entry equals the derived URL, so it only matters for future exceptions | Master scenarios are imported records keyed by id, not uma-racer's hand-written ladder |
| P27 | 2026-10-10 | The GameTora cache is **keyed by dataset version** (`.cache/<dataset>.<version>.json`, older versions pruned; `--offline` reuses the cached manifest). Normalizers read GameTora's **current field name first and older names after it** (`pick(raw, 'name_ja', 'jp_name')`) | uma-racer's cache reused a stale copy until `--refresh`. GameTora renamed `jp_name`/`en_name`/`name_jp` to `name_ja`/`name_en` between 2026-09-19 and 2026-10-10; a rename must never break an import or reach the schema |
| P28 | 2026-10-10 | `@luismlorenzana/uma-data` ships **ESM and CommonJS** builds made with `tsc` (no bundler), runs in browsers and Node 20+ (WebCrypto for hashes), and exposes `@luismlorenzana/uma-data/testing` with synthetic master records and an in-memory release | Game web apps are ESM; uma-racer's API deploys as CommonJS; games need valid fixtures without real data |
| P29 | 2026-10-10 | Package versions use **Changesets, versioned on `main` by Claude** (`pnpm version-packages`, committed with the change) and **published by CI** (`release-packages.yml`: `changeset publish` with `GITHUB_TOKEN`, `packages: write`) whenever `packages/**` changes. No "Version Packages" pull request; private workspace packages aren't versioned | The PR flow needs the repo setting that lets Actions open pull requests; Claude already pushes to `main` (owner, 2026-10-10). Delegated agents add a changeset in their PR and Claude versions after merging |
| P30 | 2026-10-10 | `lint` is a TypeScript type-check (`tsc --noEmit`) per package, as in uma-racer; no ESLint for now. `turbo.json` sets `agentGuidance: false` so Turbo 2.11+ doesn't write its own block into `AGENTS.md` | Same baseline as uma-racer (§4); strict TS with `noUncheckedIndexedAccess` catches what matters here. `AGENTS.md` is the owner's file |
| P31 | 2026-10-10 | The local release lives in `content/release/` (gitignored) with the bucket's file paths plus `manifest.json`. Download caches stay per package (`scripts/data/.cache`, `scripts/assets/.cache`) as in uma-racer. **Private inputs** a fresh clone needs: `content/overrides/` (scenario crests, optional bust pins) and the owner's wiki art folder for `pnpm assets:import -- --source dir:<path>` once | One layout from import to bucket; caches and private inputs are explicit, so a fresh clone reproduces the same release version |
| P32 | 2026-10-10 | Track names come from the importer's table: uma-racer's 15 venues plus **Santa Anita Park (10202)**, home of the game's only 10202 race (American Oaks). Track 10203 has courses but no races, so its name stays null | GameTora's racetracks have no names; a guessed name would be worse than none |
| P33 | 2026-10-10 | `Character.realHorseSex` maps GameTora's `sex` exactly as uma-racer did (1 male, 2 female), even for characters without a real horse | Keeps uma-racer's behaviour identical through the switch; `kind`, `fictional` and `realHorse` tell games when it's meaningful |
