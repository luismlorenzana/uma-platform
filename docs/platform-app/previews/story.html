Publishing: how the farm's story reaches the game

Settled in uma-farm's F56 and the notes F40 gained while the romance core was built.

  1. Release. pnpm story:release validates the drafts and refuses a pack where any cast Uma lacks her bible or her arrival scene. Routes may be partial.
  2. Hash. An index, story.json, and each file named by its hash. The index lists which events are scripted.
  3. Publish. pnpm story:publish uploads to gs://uma-farm-content. The bucket has your yes.
  4. Serve. farm-api, behind the owner guard; the web checks each hash and keeps it on the device.
  5. Go live. The romance turns on with save v4 and the wipe. Later waves are new pack versions, with no code change.

The go-live needs 20 bibles and 20 arrival scenes

Not the three pilot routes. So the arrival scenes are written with layer 2, ahead of the pilot.

F56 waits for the pack "on this Mac"

The drafts are on the Windows PC. The review copy closes the gap: pnpm story:pull farm --drafts on whichever machine publishes (AP68).
